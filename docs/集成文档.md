## 三、厂商库动态加载架构（本次新增）

### 3.1 设计目标

解决不同厂商提供 `.dll`、`.edz`、`.compiled-library` 等库文件的统一加载和调用问题，无需在代码中硬编码 P/Invoke 声明。

### 3.2 目录结构

```
HardwareModularWorkflow.Controller/
├── VendorLibraries/          # 厂商库资源目录（.gitignored）
│   ├── LeadSys/
│   │   ├── EPAN.dll         # 雷赛 PLC 库（用户放置）
│   │   └── manifest.json    # 厂商清单（描述 API 接口）
│   └── ZLG/
│       ├── zlgcan.dll       # 周立功 CAN 库（用户放置）
│       └── manifest.json    # 厂商清单
├── Loader/
│   └── VendorLibraryLoader.cs      # 统一加载器（扫描 + 缓存）
├── Reflection/
│   ├── VendorManifest.cs           # 清单模型（JSON 反序列化）
│   └── DynamicDllInvoker.cs        # 核心反射调用器
├── Adapter/
│   └── IControllerAdapter.cs       # 控制器适配器接口
├── Plc/
│   ├── LeadSysPlcController.cs     # 旧版模拟实现（保留兼容）
│   └── ReflectivePlcController.cs  # 新版反射实现（自动回退模拟）
└── Can/
    ├── ZlgCanController.cs         # 旧版模拟实现（保留兼容）
    └── ReflectiveCanController.cs  # 新版反射实现（自动回退模拟）
```

### 3.3 核心组件

| 组件 | 职责 | 关键类 |
|------|------|--------|
| **VendorManifest** | 描述厂商库的元数据、API 接口、依赖关系 | `VendorManifest`, `VendorApiEntry`, `VendorLibraryEntry` |
| **DynamicDllInvoker** | 通过 `NativeLibrary.Load` + `GetProcAddress` + `Marshal.GetDelegateForFunctionPointer` 动态调用 Native DLL | `DynamicDllInvoker` |
| **VendorLibraryLoader** | 扫描 `VendorLibraries/` 目录，加载所有 `manifest.json`，创建并缓存驱动 | `VendorLibraryLoader`, `NativeDllDriver`, `ManagedAssemblyDriver` |
| **Reflective Controller** | 通过 `IVendorLibraryDriver` 调用厂商 API，库缺失时自动回退到模拟实现 | `ReflectivePlcController`, `ReflectiveCanController` |
| **ControllerFactory** | 根据配置中的 `VendorName` 选择反射模式或模拟模式，创建对应控制器 | `ControllerFactory` |

### 3.4 工作流程

```
1. 应用启动 → ServiceRegistration 注册 VendorLibraryLoader（Singleton）
2. VendorLibraryLoader 异步扫描 VendorLibraries/ 目录下的所有 manifest.json
3. 用户配置控制器（数据库 ControllerEntity）→ 指定 VendorName（如 "LeadSys"）
4. ControllerFactory.GetOrCreateAsync():
   a. 若 VendorLibraryLoader 已加载该厂商 → 创建 ReflectivePlcController（反射调用 DLL）
   b. 若厂商库不可用 → 自动回退到 LeadSysPlcController（模拟实现）
5. ReflectivePlcController 内部通过 IVendorLibraryDriver.Invoke("ReadRegister", ...) 调用厂商 API
```

### 3.5 manifest.json 示例（LeadSys）

```json
{
  "manifestVersion": "1.0",
  "vendorId": "LeadSys",
  "vendorName": "雷赛智能",
  "controllerType": "Plc",
  "libraryType": "NativeDll",
  "platform": "x64",
  "libraries": [{ "path": "EPAN.dll", "role": "Primary" }],
  "apis": [
    {
      "name": "OpenDevice",
      "entryPoint": "EPAN_OpenDevice",
      "callingConvention": "StdCall",
      "parameters": [
        { "name": "ipAddress", "type": "string" },
        { "name": "port", "type": "int" },
        { "name": "timeoutMs", "type": "int" }
      ],
      "returnType": "IntPtr"
    }
  ]
}
```

### 3.6 使用方式

**步骤 1：放置厂商库文件**
```bash
# 将厂商提供的 DLL 放置到对应目录
HardwareModularWorkflow.Controller/VendorLibraries/LeadSys/EPAN.dll
HardwareModularWorkflow.Controller/VendorLibraries/ZLG/zlgcan.dll
```

**步骤 2：编辑 manifest.json**（已提供示例，按需调整 API 签名）

**步骤 3：重启应用** → `VendorLibraryLoader` 自动扫描加载

**步骤 4：配置控制器** → 在 UI 的"控制器配置"页面选择对应厂商

### 3.7 优势

- **无需硬编码 P/Invoke**：`manifest.json` 描述 API，`DynamicDllInvoker` 运行时生成委托
- **支持多厂商**：同一套代码支持 LeadSys/ZLG/Siemens/Beckhoff 等任意厂商
- **自动回退**：厂商库缺失时无缝降级为模拟模式，不影响开发和测试
- **库文件可热替换**：运行时替换 DLL 后重启即可生效
- **支持 Managed Assembly**：除 Native DLL 外，也支持 .NET 托管程序集的反射调用

## 五、依赖注入注册清单

```csharp
// Core 层（ServiceRegistration.cs）
services.AddSingleton<VendorLibraryLoader>(provider => {
    var loader = new VendorLibraryLoader(VendorLibraryLoader.GetDefaultVendorLibrariesPath());
    _ = Task.Run(async () => await loader.ScanAndLoadAllAsync());
    return loader;
});
services.AddSingleton<ControllerFactory>(provider => {
    var vendorLoader = provider.GetService<VendorLibraryLoader>();
    return new ControllerFactory(vendorLoader);
});
```

## 六、关键架构决策

1. **厂商库动态加载**：`manifest.json` + `DynamicDllInvoker` + `VendorLibraryLoader` 实现零硬编码 P/Invoke
2. **自动回退机制**：`ReflectivePlcController` / `ReflectiveCanController` 在厂商库不可用时自动降级为模拟模式
3. **ViewModel Singleton**：页面状态在切换导航时保留
4. **DbContext 直接注入 VM**：支持级联保存
5. **事件总线实时订阅**：基于 Channel 的异步内存总线
6. **SQLite 兼容性**：`[Column(TypeName = "TEXT")]` 替代 `nvarchar(max)`
7. **MaterialDesign 资源适配**：`MaterialDesign2.Defaults.xaml`
