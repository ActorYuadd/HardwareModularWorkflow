## 一、项目背景与需求确认

用户最初提供 `README.md`，要求分析项目框架和分层结构，建立开发文档。

**核心定位**：HardwareModularWorkflow 是一款以**硬件**为中心的模块化工作流软件。

### 关键约束
- 通讯控制器：Plc 和 Can 两种，需兼容不同厂商 DLL
- 基本功能覆盖，暂不考虑厂家特色/私密协议
- 硬件模块类型多（电机、制温、制冷、自定义）
- 工作流支持独立运动和同步（等待完成）
- 技术栈：CommunityToolkit.Mvvm, Microsoft.Extensions.DependencyInjection, Antelcat.I18N.WPF, MahApps.Metro, MaterialDesignThemes.MahApps

## 三、架构重构（第二轮）

### 3.1 用户明确要求：以硬件为核心

用户回复：
> "核心」是 硬件模块工作流。对于外设硬件来说是个核心……其他功能都是围绕硬件/电路板进行分层的。"

**架构重构决策**：
- 将 `MotioncontrolPlc` 扩展为 `Controller` 项目（涵盖 Plc + Can）
- Hardware 项目作为**中心层**，不依赖任何其他项目
- Controller 作为硬件的**适配器/基础设施**
- Workflow 只组合 Hardware 模型，不感知 Plc/Can 细节

### 3.2 以硬件为中心的同心圆分层

```
Wpf (UI)
  ↓
Core (调度编排)
  ↓
Workflow (模块/流组合)
  ↓
Hardware ⭐ (类型系统、命令抽象、控制器接口定义)
  ↓
Controller (Plc/Can 厂商适配器)
  ↓
物理设备
```

## 四、六大问题决策

用户在文档基础上逐条确认 6 个待解决问题：

### 问题 1：命令映射位置
**决策**：Hardware 发语义命令，Controller 完全翻译。Hardware 只关心"做什么"，Controller 关心"怎么做"。

### 问题 2：电机编码器是否区分
**用户问**：上位机是否需加入带编码/不带编码特性？
**决策**：区分，但用参数化方式 `HasEncoder: bool`，不拆独立类型。
- true：上位机读取反馈做闭环监控
- false：只做开环命令下发

### 问题 3：异步冲突处理
**决策**：四层协作策略
- Controller：`Task.Run` + `SemaphoreSlim` 包装同步 DLL
- Hardware：命令标记 `IsAsync`
- Workflow：同步硬件串行、异步硬件并行
- Core：同一控制器资源锁串行化

### 问题 4：自定义硬件扩展
**决策**：第一阶段 JSON Schema + 命令模板；第二阶段预留插件 DLL。

### 问题 5：工作流执行机制（重大设计）
**用户方案**：
> "嵌套不做限制，每个动作作为异步，总合成线程集合（50条上限），根据 CancellationToken 终结"

**分析调整**：
- "线程集合" → 改为 **Task 集合**（避免线程耗尽）
- 使用 `SemaphoreSlim(50)` 限制并发
- 嵌套用**队列/栈**调度而非递归，避免栈溢出
- CancellationToken 分两层：调度层（未开始的任务取消）+ Controller 层（尝试中断已下发命令）
- 循环检测：不做静态层级限制，运行时通过 `ExecutionPath` 检测循环

### 问题 6：多控制器绑定
**决策**：添加流/模块时绑定控制器，配置信息存入数据库 `Controllers` 表。

```csharp
// 后台循环
await foreach (var item in _queue.Reader.ReadAllAsync(ct))
{
    await _concurrencyLimit.WaitAsync(ct);
    var task = ExecuteWorkItemAsync(item, ct)
        .ContinueWith(_ => _concurrencyLimit.Release());
    _runningTasks.Add(task);
}
```

## 八、关键架构决策回顾

1. **Hardware 为中心**：Hardware 项目不依赖任何其他项目，Controller 实现 Hardware 定义的接口
2. **命令映射**：Hardware 发语义命令（`MoveTo(100)`），Controller 翻译为厂商指令
3. **电机编码器**：参数化 `HasEncoder`，不拆独立类型
4. **异步调度**：`Channel + SemaphoreSlim(50)`，嵌套用队列而非递归
5. **循环检测**：不做静态层级限制，运行时 `ExecutionPath` 检测
6. **多控制器**：添加硬件实例时绑定控制器，配置存 `Controllers` 表
7. **自定义硬件**：第一阶段 JSON Schema，第二阶段预留插件 DLL
8. **事件总线**：基于 `Channel` 的异步内存总线，发布者不阻塞
