## 一、项目概述

**HardwareModularWorkflow** 是一款以**硬件**为中心的模块化工作流软件。

- 根据编辑的工作流进行独立运动，亦可同步（等待某工作流完成）
- 工作流中可添加其他工作流（但禁止对当前工作流的自引用）
- UI 画风参考：https://github.com/yoi102/VisionProcess

### 核心约束
- 通讯控制器：Plc 和 Can 两种，需兼容不同厂商 DLL
- 基本功能覆盖，暂不考虑厂家特色/私密协议
- 硬件模块类型：电机（带编码/不带编码）、制温、制冷、自定义
- 嵌套层级不做限制，运行时检测循环

## 三、项目架构（六个项目）

### 3.1 分层关系

```
HardwareModularWorkflow.Wpf              (UI 层)
  ↓ 依赖
HardwareModularWorkflow.Core             (调度编排层)
  ↓ 依赖
  ├── HardwareModularWorkflow.Workflow   (工作流引擎)
  ├── HardwareModularWorkflow.Controller (通讯控制器：反射动态加载 + 模拟回退)
  ├── HardwareModularWorkflow.Db         (数据持久化)
  └── 均依赖
      HardwareModularWorkflow.Hardware   (硬件核心层) ⭐ 中心
```

**关键原则**：
1. Hardware 项目不依赖任何其他项目，只定义抽象和模型
2. **Controller 层支持反射动态加载**：通过 `manifest.json` 描述厂商 API，运行时 `DynamicDllInvoker` 生成委托调用，无需编译时硬编码 P/Invoke
3. **自动回退机制**：厂商库不可用时自动降级为模拟模式，确保无硬件环境下仍可开发和测试

## 五、关键架构决策（不可违反）

1. **Hardware 为中心**：Hardware 项目不依赖任何其他项目，只定义抽象和模型
2. **厂商库动态加载**：`manifest.json` 描述厂商 API → `VendorLibraryLoader` 扫描加载 → `DynamicDllInvoker` 运行时生成委托调用。无需硬编码 P/Invoke，支持任意厂商
3. **自动回退机制**：厂商库缺失时 `ReflectivePlcController` / `ReflectiveCanController` 自动降级为模拟模式，确保开发和测试不受硬件限制
4. **命令映射**：Hardware 发语义命令（`MoveTo(100)`），Controller 完全翻译为厂商指令
5. **电机编码器**：参数化 `HasEncoder: bool`，true 时读取反馈做闭环，false 时开环下发
6. **异步调度**：`Channel<WorkItem> + SemaphoreSlim(50)`，嵌套用队列而非递归
7. **循环检测**：不做静态层级限制，运行时 `ExecutionPath.HasVisitedFlow()` 检测
8. **多控制器**：添加硬件实例时绑定控制器，配置存 `Controllers` 表
9. **自定义硬件**：第一阶段 JSON Schema + 命令模板，第二阶段预留插件 DLL
10. **事件总线**：基于 `Channel` 的异步内存总线，发布者不阻塞，多订阅者独立失败
11. **硬件目录（第一期）**：硬件类别与控制能力分离。Definition 必须选择类别和控制能力；实例页按类别筛选定义，并按控制能力筛选兼容控制器。现有 `Type` 保留到运行时驱动解析改为 Profile 的第二期。
12. **Profile 驱动解析（第二期）**：`HardwareDriverFactory` 从 Definition 的 `ControlProfile.DriverKey` 解析已安装的 Profile Driver，并验证 `RequiredControllerType`。类别仅决定兼容硬件模型；Profile 决定执行驱动。未安装 Driver、未绑定控制器或控制器类型不符时会抛出明确配置错误。
13. **Profile 命令集（第三期）**：Profile 的 `CommandDefinitionsJson` 声明可用语义命令、异步属性和必填参数。模块编辑器根据所选硬件刷新命令下拉；保存和运行时都会校验命令和必填参数，防止旧工作流调用已不支持的命令。

2. **命令映射**：Hardware 发语义命令（`MoveTo(100)`），Controller 完全翻译为厂商指令
3. **电机编码器**：参数化 `HasEncoder: bool`，true 时读取反馈做闭环，false 时开环下发
4. **异步调度**：`Channel<WorkItem> + SemaphoreSlim(50)`，嵌套用队列而非递归
5. **循环检测**：不做静态层级限制，运行时 `ExecutionPath.HasVisitedFlow()` 检测
6. **多控制器**：添加硬件实例时绑定控制器，配置存 `Controllers` 表
7. **自定义硬件**：第一阶段 JSON Schema + 命令模板，第二阶段预留插件 DLL
8. **事件总线**：基于 `Channel` 的异步内存总线，发布者不阻塞，多订阅者独立失败

### 步骤 5：常见问题

**Q：如何添加新的厂商库（如 Siemens、Beckhoff）？**
A：1. 在 `Controller/VendorLibraries/` 创建新目录（如 `Siemens/`）
   2. 放置厂商 DLL 文件到该目录
   3. 复制 `manifest.json` 模板，根据厂商头文件编辑 API 签名（函数名、参数类型、返回类型、调用约定）
   4. 重启应用，`VendorLibraryLoader` 自动扫描加载
   5. 在 UI 控制器配置页面选择新厂商

**Q：编译报错找不到 zlgcan.dll？**
A：将 `docs/周立功/zlgcan_x64/zlgcan.dll` 复制到 `HardwareModularWorkflow.Controller/VendorLibraries/ZLG/` 目录。项目已配置 `.gitignore` 不提交 DLL 文件，仅提交 `manifest.json`。

**Q：PLC 控制器无法连接？**
A：检查 `VendorLibraries/LeadSys/` 目录下是否存在 `EPAN.dll` 和 `manifest.json`。若缺失则自动回退到模拟模式，不影响测试。

**Q：manifest.json 中的 API 签名如何确定？**
A：1. 使用 `dumpbin /exports xxx.dll` 或 `Dependency Walker` 查看 DLL 导出函数
   2. 根据厂商提供的头文件（.h）确定参数类型和调用约定
   3. 将 C 类型映射为 C# 类型（如 `int`→`System.Int32`，`void*`→`System.IntPtr`）

**Q：子流嵌套不工作？**
A：`WorkflowScheduler.ResolveAndQueueSubFlowAsync` 已通过 `IFlowResolver` 注入 `FlowResolver`，从数据库查询 Flow 对象。需验证 `FlowService.GetByIdAsync` 是否正确返回子流定义。
A：将 `docs/周立功/zlgcan_x64/zlgcan.dll` 复制到 `HardwareModularWorkflow.Controller` 输出目录。

**Q：PLC 控制器无法连接？**
A：需先解压 `docs/雷赛/MC500系列EPAN库文件.rar`，根据头文件启用 `LeadSysPlcController.cs` 中的 P/Invoke。

**Q：子流嵌套不工作？**
A：`WorkflowScheduler.ResolveAndQueueSubFlowAsync` 当前返回 `NotImplementedException`。需实现 `IFlowResolver` 从数据库查询 Flow 对象。

**Q：如何添加新页面？**
A：1. 在 `Wpf/Views/` 创建 XAML UserControl；2. 在 `Wpf/ViewModels/` 创建 ViewModel；3. 在 `MainWindowViewModel.InitializeNavigation()` 添加导航项；4. 在 `App.xaml.cs` 注册 ViewModel 到 DI 容器。
